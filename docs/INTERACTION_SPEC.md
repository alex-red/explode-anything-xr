## 1. Session and space

- **Immersive AR** with passthrough by default. A backdrop toggle cycles passthrough → dimmed → virtual (P1).
- **Seated** reference space (`local`), with recenter always reachable.
- The system anchor sits about **0.65 m** in front of the head, slightly below eye level. The collapsed object is about 30 cm across.
- The exploded layout fits a **60°×50° cone** at 0.5–0.8 m. That is safe for the VR Glasses' ~70×66° field of view ([REVIEW.md §2 #1](REVIEW.md#2-factual-corrections)). Every target is within **0.65 m reach**.
- Keep content slightly *beyond* the hands. In passthrough, virtual objects draw over your real hands.

The authoritative steps are the lesson definitions in `apps/quest/src/content/*.bundle.json`, generated by `bun run content:generate`. The tutorial is skippable (**Skip tutorial**). No login, no voice permission, no required narration.

## 3. Gesture dictionary

| Input | Behavior | Safeguards / fallback |
|---|---|---|
| **Hand ray + pinch** (`select`) on a node | Select / focus, on release | Generous colliders; hover highlight; no dwell. A pinch whose ray slides off before release is not a press. The controller ray works identically |
| Ray + pinch on a toolbar button | Run that command | Buttons ≥ 4 cm, poke-able up close |
| **Both hands pinch and pull apart** | Explode factor follows the change in hand distance (0→1). Past fully exploded, the same pull zooms in (to 2×) | Engages only when both pinches start within about 500 ms. **Explode/Collapse** buttons do the explode part. Keyboard `E`, and `+` / `-` for zoom, in the emulator |
| Both hands pinch and push together | Zoom out, then collapse. A collapsed model is always full size | Never collapses while an edge is in the tray |
| Both hands pinch and turn like a steering wheel | Roll the model about the line of sight, following the hands | Small angles (under about 6°) are ignored, so a straight pull does not roll it; needs the hands at least 12 cm apart. Keyboard `,` / `.` |
| Both hands pinch, one forward and one back | Spin the model about its vertical axis | Same safeguards. Keyboard `[` / `]` |
| Both hands pinch and push away or pull closer | Tilt the model about the horizontal axis (to 60°): pulling tips the top toward you | The first 2 cm are ignored. Keyboard PageUp / PageDown |
| Both hands pinch and move together, sideways or up and down | Carry the model | Held within reach of its authored place. Arrow keys |
| **One hand pinches a part and drags** | Move the model. Only the model moves; panels stay put | A pinch that travels under 3 cm is still a click; a drag drops that click. Arrow keys |
| **One hand pinches empty space and drags** | Turn the model: sideways spins it, up and down tilts it (to 60°) | Never starts from a toolbar or panel control. Keyboard `[` / `]` and PageUp / PageDown. **Recenter** resets move, zoom, turn and tilt |
| **Gestures** button | Shows or hides a one-card guide to all of the above, below the model | Hidden by default. Keyboard `G` |
| Select an edge plug → **Unplug** | Detach into the sandbox tray | Only `is_mutable_in_sandbox` edges |
| Select a socket while a plug is detached | Repair attempt | A wrong socket shows feedback, plus the expected socket after the 2nd miss |
| **Undo** / **Reset** | Drop the last undoable event / restart the lesson | Always visible on the toolbar |
| Context chips: **Explain this**, **Why did that fail?**, **What depends on this?**, **Hint** | Tutor turn | Works offline (scripted) |
| Voice | P2 only | Never required |

**Not used:**

- head-gaze targeting (only the last-resort fallback);
- pose detection ("open palms");
- dwell;
- precision fingertip choreography.

IWSDK facts that shaped this ([ADR-0001](adr/0001-engine.md)): `GrabSystem.useHandPinchForGrab` defaults to `false`, proximity grab uses squeeze, and distance grab uses trigger. P0 is therefore built on ray + `select`.

## 4. Visual language

- **A hologram** ([ADR-0022](adr/0022-hologram-look.md)): dark translucent faceted bodies with bright rims and scanlines, soft additive halos, energy-conduit edges, and a projector stage under the model that it boots up from. Panels are dark glass plates with cut corners and a glowing edge. No full-screen post-processing or bloom ([ADR-0013](adr/0013-render-budget.md)).
- **State colors**, each paired with a shape or animation and a text badge:

  | Color | State | Paired cue |
  |---|---|---|
  | Hologram blue (violet for routes) | Normal | — |
  | Gold | Traced path | Moving flow pulses, on the edges and as particles. No other edge has travelling light |
  | Teal | Selected / user action | Outline |
  | Coral | Disconnected / affected | Dimmed and dashed, plus a "✕" badge |

- **Truth badges:** `Observed`, `In source`, `Teaching model`, `Hypothesis` (dotted connector), `Unknown`.
- **Labels:** at most about 30 visible; prioritized by importance and focus; sized for Quest 3S readability.
- **Motion:** eased authored interpolation between collapsed and exploded positions; no physics debris.

## 5. Panels

| Panel | Placement | Content |
|---|---|---|
| Caption bar | Below the object, ~0.55 m | Current step caption and feedback |
| Toolbar | Low and to the right, within reach | Explode, Collapse, Trace, Unplug, Undo, Reset, Next, Skip, chips |
| Evidence panel | Right of the object | Source excerpt (≤ 12 lines, large monospace), path:line, revision, badge; or the run record (command, failing tests, recorded at) |

## 6. Tutor persona and teaching policy

**Persona:** a concise, curious technical guide. No flattery. It states uncertainty plainly.

> "This connection is in the source. With it removed, a recorded test run fails 2 tests. Want to see the run, or try reconnecting it first?"

**Policy:**

- **Predict before reveal.** Ask before showing.
- **The learner acts.** Breaking and repairing are only possible by hand.
- **Feedback grounded in state.**
- **Hints after mistakes.**
- **Abstain when evidence is missing.**

**Engine-enforced:**

- The tutor cannot advance lessons, grade, break or repair. Those actions are not in `TUTOR_ACTION_TYPES`.
- Predictions are scored by `reduce()`.
- A wrong prediction records the lesson's misconception tag.

**Triggers (no keyboard in XR):**

| Trigger | Fired by |
|---|---|
| `explain_selection` | "Explain this" chip |
| `what_depends` | "What depends on this?" chip |
| `why_failed` | "Why did that fail?" chip |
| `hint` | "Hint" chip, or automatically after 2 misplugs |
| `free_text` | Live proxy only; P2 with voice |

## 7. Accessibility and comfort

**Baseline (P0):**

- Complete functionality with hands and no controllers. The controller ray also works.
- Seated; every target within ~0.65 m and inside the cone; recenter, reset and pause/resume always available.
- Every gesture has a button equivalent, except moving, zooming and turning the model: those have Recenter to undo them and keys in the emulator, but no buttons of their own ([ADR-0021](adr/0021-view-manipulation.md)).
- Captions for every narrated line, always on.
- Color is never the only signal (see §4).
- No eye tracking required (Quest 3/3S have none).

**P1:**

- Reduced-motion toggle (shorter, no orbital moves).
- Text-size toggle.
- One-handed path: buttons only.
- Left-handed toolbar mirror.

**Comfort QA:** two seated heights, left-handed use, glasses, tracking loss, wrist occlusion, recentering mid-lesson. See [QA_MATRIX.md](QA_MATRIX.md).
